# StageConverter

TiledのJSONマップ（`.tmj`）にあるタイルレイヤーとオブジェクトレイヤーを、
Gameが読み込む `*.stage.json` 形式へ変換する独立したGUIアプリです。

## 対象範囲

- 表示中のタイルレイヤーとオブジェクトレイヤーを変換します。
- 有限マップと、チャンクを使う無限マップの両方に対応します。
- グループレイヤー内のタイル／オブジェクトレイヤーにも対応します。
- JSON形式の外部タイルセット（`.tsj`）と埋め込みタイルセットに対応します。
- `typeId` カスタムプロパティを持つタイルとオブジェクトだけを出力します。
- 非表示要素と `typeId` のない編集用要素はスキップします。
- 画像レイヤーとTiledの外部オブジェクトテンプレートは変換しません。
- 入力はJSON形式の `.tmj` のみです。XML形式の `.tmx` は対象外です。
- 外部タイルセットもXML形式の `.tsx` ではなく `.tsj` を使用してください。
- タイルレイヤーの保存形式はCSV（JSON上の `data` が配列になる形式）を使用してください。
- 反転・回転フラグ付きタイルは、現在のゲーム形式で鏡像を表せないためエラーにします。

## Tiled側の設定

### タイルレイヤー

ブロック用タイルセットを作り、タイルセットエディターで各タイルへ次のカスタム
プロパティを追加します。タイルセット全体ではなく、個々のタイルへ設定してください。

| 名前 | Tiledでの型 | 必須 | 内容 |
|---|---|---:|---|
| `typeId` | int | はい | Gameのタイル定義に登録した正のID |
| `scaleX` | float | いいえ | X方向の倍率。省略時は1.0 |
| `scaleY` | float | いいえ | Y方向の倍率。省略時は1.0 |

例えば32×32ピクセルのタイルを使い、Pixels Per Unitを32にすると、タイルレイヤーの
1マスがゲーム内の1単位になります。空セルは出力しません。

### オブジェクトレイヤー

敵、開始位置、イベントなどを配置する各オブジェクトへ、同じカスタムプロパティを
追加します。

| 名前 | Tiledでの型 | 必須 | 内容 |
|---|---|---:|---|
| `typeId` | int | はい | Gameのタイル定義に登録した正のID |
| `scaleX` | float | いいえ | X方向の倍率。省略時は1.0 |
| `scaleY` | float | いいえ | Y方向の倍率。省略時は1.0 |

マップ自体には任意で文字列プロパティ `stageName` を設定できます。GUIのステージ名欄が
空の場合はこの値を使い、それもなければ入力ファイル名を使います。

## 実行方法

### カメラ表示範囲（CameraBounds）

既存の `BossApproachCameraZone` と同様に、Tiledのオブジェクトレイヤーで設定します。

1. 名前が **`CameraBounds`** のオブジェクトレイヤーを作成します（大文字・小文字も一致させます）。
2. カメラに映してよい領域を、回転なしの長方形で囲みます。
3. 通常どおりStageConverterで変換します。`typeId`などのカスタムプロパティは不要です。

出力JSONの `cameraBounds` 配列には、各長方形の `minX`、`maxX`、`minY`、`maxY` が
ゲーム単位で入ります。これはカメラの中心の移動範囲ではなく、**画面全体を収めたい範囲**です。
Y座標は他のゾーンと同様に上下を反転し、グループ／レイヤーのオフセットも加算します。
非表示のレイヤー・長方形は出力しません。回転した長方形、幅・高さが0以下のもの、
長方形以外の形状は変換エラーになります。未設定の場合は空配列です。

`Data/Stage/LaboratoryCourse.tmj` には開始エリア付近の仮範囲（ゲーム座標でX: -8〜36、
Y: -8〜20）を配置しています。必要に応じてTiledで調整してください。
`Sample/BioLaboratoryStage.tmj` には空のレイヤーを追加しています。`Sample/CameraBoundsSample.tmj` は
1つの長方形を含む変換確認用サンプルです。

Game側では、cameraSection未指定の範囲は合成領域に画面全体を収める方式、明示的なセクションはセクション全体の外枠と画面位置に応じた下限で追従を制限する方式です。
隣り合う長方形をまたいで画面を配置でき、重なりの順番やプレイヤーの所属矩形による
切り替えはありません。未指定方式では凹みや穴を表示範囲から除外します。明示的なセクションでは下限以外の凹みや穴も映り得ます。プレイヤーが範囲外に
出ても制限は継続します。空配列の場合は制限しません。

通常追従では、プレイヤーの足元がCameraBoundsの合成領域内にあるときだけ表示を優先します。足元から高さ2までの体に余白を設け、
その全体が見えるカメラ位置とCameraBoundsの許容位置を両立できる場合は両方を守ります。
両立できない場合は、プレイヤーを画面外へ押し出す方向の制限を緩めます。
その際は範囲外の背景が映ることがあります。急な上下移動で追従が遅れた場合にも適用します。
プレイヤーが領域外（内部の穴を含む）に出た場合は表示優先の補正を行わず、通常の範囲制限を維持します。

現在の通常カメラの画面寸法（左右8.176、下4.622、上4.338ゲーム単位）を使います。
cameraSection未指定時、画面が収まる位置が領域全体に一つもない場合は、各矩形を画面寸法分だけ縮め、
狭すぎる軸は中央に固定した候補のうち、追従目標に最も近い位置を使います。
この場合、画面全体を領域内へ収めることはできません。範囲を広げるか、専用カメラを
使ってください。離れた部屋など、画面を収められる位置がつながっていない場所では
明示的なセクション内では、各矩形の継ぎ目・凹みを理由に構図を切り替えません。
ボス部屋・ボス前通路の固定カメラは引き続き優先します。

#### セクションと切り替え領域

- CameraBoundsの各長方形に、文字列のカスタムプロパティ `cameraSection` を設定します。
- 同じ値の長方形は一つの連続したカメラ範囲として扱います。内部の矩形ごとに補正先を選び直しません。
- 明示的なセクションでは全矩形を囲む外枠でカメラ位置を制限し、通常の先読み・上下追従を維持します。
  下限は画面の横幅にかかる範囲の合成形状から求めるため、離れた低い範囲が平坦部のカメラを下げることはありません。
  プレイヤー表示と両立しない場合は表示を優先します。上側の凹みや内部の穴も画面には映り得ます。
- プレイヤーの足元がセクション内のどの矩形からも外れた場合、カメラのXY位置をその場に保持します。
  足元がセクションに戻ると追従を再開します。切り替え領域を通過した場合は次のセクションへ切り替えます。
- 未設定の長方形は空のセクション名として、従来どおり一つのグループになります。
- `CameraSectionTriggers` というオブジェクトレイヤーを作り、切り替え位置を長方形で囲みます。
  その長方形にも、切り替え先を示す文字列 `cameraSection` を設定します。
- プレイヤーの足元が切り替え領域に入ると、そのセクションの構図へ即時に切り替えます。
  CameraBoundsの境界だけではセクションを変えません。往復させる場合は境界の両側へ別々の切り替え領域を置きます。
- 初回・大きなワープ時は、移動先でプレイヤーを含むセクションを選び直します。
- 切り替え領域は映してよい範囲を広げません。変換JSONでは `cameraBounds` 内に
  `cameraSection` と `isSectionTrigger: true` を持つ要素として保存します。

現在の `LaboratoryCombinedCourse.tmj` は、First＋tutorialが `first`、Secondが `second`、
Third〜Sixthが `third` です。境界のX=72とX=118.9375の両側2単位に切り替え領域を配置しています。
ジャンプ中も通れるよう、切り替え領域のYは-8〜34としています。
調整後は通常どおりStageConverterで再変換してください。

ソリューションで `StageConverter` をビルドした後、次のexeをダブルクリックします。

```text
bin\x64\Debug\StageConverter.exe
```

GUIが開いたら、次の順番で操作します。

1. 「入力TMJファイル」の参照ボタンからTiledの `.tmj` を選びます。
2. 自動入力された出力先を確認し、必要なら「出力stage.json」の参照ボタンで変更します。
3. Pixels Per Unitを入力します。初期値は32です。
4. 必要な場合だけステージ名を入力します。
5. 「変換実行」ボタンを押します。

パスは直接入力することもできますが、相対パスの基準位置による間違いを避けるため、
通常は参照ボタンを使って絶対パスを指定してください。

Pixels Per Unitは「Tiled上の何ピクセルをゲーム内の1単位にするか」です。
例えば32なら、TiledのX座標64はゲームのX座標2になります。

## 座標の変換規則

オブジェクトレイヤー:

- X座標: `(オブジェクトのx + レイヤーのoffsetx) / Pixels Per Unit`
- Y座標: `-(オブジェクトのy + レイヤーのoffsety) / Pixels Per Unit`
- 回転角: `-オブジェクトのrotation`

タイルレイヤー:

- X座標: `(セルX × tilewidth + レイヤーのoffsetx) / Pixels Per Unit`
- Y座標: `-(セルY × tileheight + レイヤーのoffsety) / Pixels Per Unit`
- 回転角: 0

Tiledは画面下方向がYの正方向で、Gameは上方向がYの正方向なので、Y座標と回転角の
符号を反転します。このゲームは2.5D横スクロール用なので、Z座標は出力しません。

## 結果表示

変換に成功すると、ステージ名、変換した配置数、スキップした配置数を画面下部へ表示します。
入力値やJSONに問題がある場合も、同じ場所へエラーの理由を表示します。
